## 单一正文与迁移

延续 `editorial_projects → editorial_channel_refs → article_documents/article_document_revisions`，不创建竞争性的文章业务模型。

建议通过版本化迁移为现有文档修订增加 Markdown 附属记录（按 reference_id + revision 唯一关联），并增加格式标识。Markdown 模式中每个版本的 Markdown 是权威内容；段落/块信息是同版本的派生索引，用于引用定位，不接受独立写入。保存 Markdown、修订、索引、检查失效和审计应处于同一事务。恢复历史版本通过新增修订实现。

现有段落模式在完成迁移前继续使用旧契约；不能通过简单拆行把代码、表格、图片或引用变成失真的普通段落。Markdown AST 和稳定块 ID 映射需先完成实验；发生编辑后，变化区域的证据锚点标记待复核，不继承旧事实结论。

历史 `editorial_layout_*` 保留为排版快照。首次迁移若正文和手动排版稿不同，展示选择与差异，由作者选择新正文起点；不自动覆盖任何版本。legacy 写接口对已迁移文档通过统一保存服务处理，无法无损表达时返回明确冲突，而非并行改写另一套内容。

新增 xiaohongshu 渠道时，审查所有渠道枚举、URL 映射、API 路由、图片规则、导出和检查逻辑。小红书图片页通过渠道修订关联，不冒用主稿修订。旧项目的新增渠道使用显式迁移，不在 GET 中悄悄写数据。

## 多用户与运行结构

目标结构：Next 页面/API → 身份及 workspace 授权 → 领域服务 → 持久化任务/数据库/资产；模型与平台凭据仅在服务端使用。

- 引入 users、sessions、workspaces、membership。首版每位独立作者一个私有 workspace，暂不做团队协作 UI。
- 所有私有资源及父子关系都限定 workspace，包括文章、Brief、来源、素材、画像、候选图、预览、导出、任务事件、服务和平台账号。跨空间引用禁止，ID 本身不构成权限。
- `lib/core.mjs` 可共享连接和无状态服务，不能在全局变量保存当前用户；请求和后台任务必须显式传入身份/归属。
- 旧版单一会话与无归属数据库仅继续本地模式。迁移时指定唯一 legacy owner，未分配内容不得自动向所有新用户展示。
- 首轮沿用单机持久磁盘 SQLite WAL，Next 与受控 worker 使用同一持久化存储并保持 SQLite 写入约束；远程多用户入口须在隔离和认证验收通过后启用。扩容/多节点不是本轮已实现能力。
- 私有资产去重必须限定归属或使用独立授权映射；不能沿用全局哈希 ID 作为跨用户读取依据。

建议新增逻辑实体：作者画像及建议/版本；选题、对话、创作简报；内容系列及计划项；正文 Markdown 修订和块索引；AI 会话/修改建议；服务连接/调用账本；小红书图组/页修订；平台账号/交付操作；资产关联/使用记录。均继承现有 project/reference/revision 身份。

## 写作 Agent 与画像

Agent 分为上下文组装、模型调用、结构化结果验证、建议持久化和作者接受。模型不直接写正文或数据库。

修改建议绑定 workspace、reference、baseRevision、目标块或范围、原文哈希和替换文本。接受时验证版本和原文；不匹配返回 409 并保留建议。多处逐项接受后记录已应用建议和新版本，重新映射剩余范围，无法安全映射则要求重算。初稿仅在空稿或明确的覆盖意图下直接写入。

流式生成与正文保存分离；断流保留未完成状态，不将半段结果当作成功稿。页面可显示本次使用的画像版本和素材列表。检索先用 workspace 限定的 SQLite FTS，向量检索可后续添加，不作为首轮必要依赖。

画像区分 explicit 与 inferred，建议有来源文章/修订/反馈、状态、版本、适用平台和时间。作者确认的推断才进入长期默认上下文；单篇可覆盖，支持停止学习及撤销。写作画像和视觉画像分开，来源删除后的派生记录按明确策略撤销或脱敏。

## 任务、额度与服务连接

复用图片队列的状态和预算原则，扩展持久化通用任务。新增定时调度和 worker 生命周期；不能仅依靠浏览器打开或请求结束后的 promise。

任务绑定 workspace、资源修订、服务、消耗上限和幂等键。系列按作者时区及 next_run_at 调度，持久化去重、租约/心跳、取消和暂停状态；重启后恢复，避免多 worker 重复准备。默认仅准备选题/大纲/素材，外部调用须有可撤销的计划级授权与额度。显式图片生成仍按次确认。

统一连接层支持平台连接与 BYOK，按任务选择文字/图片模型。密钥加密存储或引用密钥服务，只返回掩码；不进入浏览器存储、任务日志、提示词、导出或编辑器事件。用户自定义地址需要服务端 HTTPS、目标及 DNS 校验、禁止内网/元数据地址、重定向控制与出站限制，不能变成通用代理。

费用记账区分预计、预留、实际和待核实；任务重试不能重复扣额度。供应商超时可能已计费或已生成，应标记结果未知并查询/人工处理，不盲目重试。

## 小红书图片 Agent

不能直接复用现有“不含文字”的文章插画 prompt 来生成整页内容。

流程：固定来源修订 → 内容改编 → 结构化逐页文案/布局/视觉计划 → 作者确认与费用授权 → 图片生成/参考编辑 → 精确文字及版式合成 → 检查 → 保存图组版本 → 作者选用/导出。

每页保存 pageId、顺序、文案、布局、字体/尺寸、输入素材、prompt、模型、资产 ID、来源修订、检查报告及状态。比例和尺寸来自可配置平台规格，并在接入时复核，不把经验值写成永久平台要求。

视觉素材可调用图像服务，精确文字优先受控渲染合成；原生整图生文也可作为候选路线，但需文字检查。合成是 Agent 内部步骤，作者仍通过自然语言修改和成品预览操作，无需手动套模板。

单页重做只生成该页新修订，未选页面资产哈希不变。分页调整更新整组清单；下载从确定的图组修订生成图片包、标题/正文/话题文本，检查字体加载、溢出、图片解码与裁切，保留可恢复输入。

## 发布适配器与证据

统一适配器能力：检查账号能力、准备媒体、生成交付包、发送草稿、查询操作。不得默认每个平台都有所有方法；界面按能力展示动作。

发布操作绑定账号、workspace、渠道修订、图片清单和幂等键。图片媒体 ID 映射必须按账号与用途保存，不能把一个平台/账号的媒体标识用于另一个。超时为 outcome_unknown，先核对结果再重试。并发点击去重。

操作状态（queued/sending/succeeded/failed/outcome_unknown）与内容交付事实（exported/draft_saved/published）分开。每个事实保留 provider_response 或 author_report 证据来源及时间。导出与草稿保存不得产生 published 事实。

现有四项人工检查及不可变导出快照继续保留。凭据、账号授权、token 更新、图片上传和权限失败均独立处理；前端不承载平台 secret。
