# Content Studio · Creator V2.2 全站 UI/UX 设计说明

**状态**：设计交付稿 · 2026-10-19  
**边界**：只更新交互原型与设计文件；未修改 GitHub 仓库、未接入真实模型、采集、平台授权或数据库。  
**设计目标**：重新设计**新版 Creator 工作区**，不以旧版 StudioApp 为基础。原型为 10 个工作区 + 作品内配图模式 + 热点移动详情 + 日历月视图。

## 01 · 产品重新定义

Content Studio 是**个人内容编辑部**：用户做选题、观点和发布决定；AI 在可见授权范围内执行研究、起草、校对、配图与平台改写。它不是一个要用户自己拼流程的 Agent 控制台，也不是靠填无数表单才能开始写作的管理后台。

核心目标：**从一个灵感出发，3 次主要操作内进入可以编辑的文章；编辑时始终能看到当前平台稿、证据状态、下一步。**

核心原则：
1. **作品第一**：文章是主体，热搜、选题、来源、草稿、图像、发布、复盘都围绕作品关联。
2. **一步决策**：每个页面突出最核心的一个判断，二级设置按需打开。
3. **写作不中断**：没配置 AI 时仍能新建/编辑/手工导出；模型失败不丢草稿。
4. **信任边界**：热点≠事实；Agent 建议≠已采纳修改；草稿推送≠成功发布；推断≠真实统计。
5. **跨设备顺畅**：手机以浏览/筛选/确认/轻量编辑为主；桌面满足研究、长文写作、图像管理。

借鉴：**Easel** 的内容生命周期、热点监测、账号画像和日历；**WeWrite** 的文章任务书、来源证据、编辑质量审查、主题和风格学习。现有 Creator 的领域模型与 API 尽量保留。

## 02 · 信息架构与导航

### 一级页面（10 个）

| 页面 | 用户最关心的事情 | 核心按钮 | 关键 UX 设计 |
|---|---|---|---|
| 01 工作台 | 我现在做什么？ | 继续当前作品 | 核心作品 + 2 个待决事项 + 少量精选选题，避免 KPI 淹没主任务 |
| 02 热点雷达 | 世界上有什么值得关注的新变化？ | 关注热点 / 收为选题 | 独立一等页面；来源、趋势、分类、搜索、原始资料与未核实说明 |
| 03 选题发现 | 哪件事值得我花时间写？ | 开始创作 | 人群需求、观点角度、来源充分性与证据缺口放在同一判断卡 |
| 04 作品库 | 我写到哪里了？ | 打开作品 | 草稿中 / 审稿中 / 待发布 / 已发布；主稿和平台稿归属于同一作品 |
| 05 创作空间 | 如何把文章写好？ | 编辑 / 核查 / 配图 | 正文最大化；主稿、公众号、知乎一键切换；Agent 只出候选建议 |
| 06 发布中心 | 哪些内容真正可以交付？ | 完成发布核查 | 按平台独立核查；明确“导出、草稿、发布确认”的语义差异 |
| 07 内容日历 | 我何时产出？ | 安排内容 | 周视图/月视图；日历归于作品计划，不让 Agent 在后台悄悄发布 |
| 08 效果复盘 | 哪些决策有效？ | 分析 / 确认学习 | 平台数据来源、时间范围、缺失项；人工确认写作风格学习 |
| 09 素材库 | 这条论据/图片从哪里来？ | 导入 / 关联 | 公开线索、创作视觉、历史文章分组；来源、时间、授权与用途 |
| 10 偏好与连接 | 文章风格/模型/账号在哪里配置？ | 保存配置 | 创作者画像、文本模型、图像模型、公众号/知乎、信源与预算 |

### 作品内子工作区

`研究 → 大纲 → 写作 → 审稿 → 配图 → 发布` 是引导性阶段条，不是六个必须按顺序完成的阻塞页面。主稿和平台稿是同一作品里的独立修订，不能互相自动覆盖。配图模式在同一创作空间里切换，图片必须可单独替换。

### 移动导航

固定底部五项：`工作台 · 热点 · 选题 · 作品 · 更多`。更多进入 `发布 · 日历 · 复盘 · 素材 · 设置`。创作页内容居中，元数据与 Agent 移到正文下方/可折叠区；保留切换主稿/公众号/知乎的即时可见操作。热点点击后详情以移动抽屉呈现。

## 03 · 核心操作闭环

### 路径 A：热点 → 写作

1. 打开热点雷达，在“与我相关”筛选里查看信号；点击感兴趣热点。
2. 在详情中看事实/来源/风险，点**收为选题候选**，自动打开选题发现的对应判断卡。
3. 查看“为谁写、写什么、待核什么”，点开始写作，自动创建一个作品并打开编辑器。
4. Agent 可以查证、补证据、生成初稿，但修改必须确认采纳。
5. 针对公众号/知乎分别编辑平台稿，检查后手动交付或推草稿箱，并明确交付凭据。

### 路径 B：直接写作

工作台「新建作品」→ 输入一句标题/想法 → 编辑器。允许空文档，没有模型就继续人工写；不能要求用户先维护模型、账号、信源和八字段 brief。

### 路径 C：发布后学习

从发布记录进入复盘 → 真实账号数据与来源展示 → AI 提出“文风/选题”假设 → 作者确认 → 保存为有来源的写作偏好，允许撤销。

## 04 · 全局视觉规范

- 字体：系统 UI，中文优先 PingFang SC / Noto Sans CJK，英文 Inter 等；正文阅读线高不低于 1.7。
- 画布：`#F7F8FA`；纸张 `#FFFFFF`；导航 `#242635`；主色 `#465FD7`；文字 `#242B3B`。
- 提示色：完成 `#28764D`，待核 `#AA7339`。颜色不单独承载信息，同时用状态文案。
- 边框：`#E8EAF0`；卡片圆角约 12–17px，阴影非常浅，强调内容而非装饰。
- 1440px 桌面：235px 固定侧边栏，内容最大 1535px；编辑页中央优先，侧栏收敛。
- 393px 移动：单列内容、底部 5 项导航；横向阶段条可以滚动，页面整体不允许横向溢出。
- 常用交互：主操作一枚实色按钮；次要操作中性描边；次次确认只保留在高成本/涉外发送/正式发布环节。
- 无内容：不能空白，应提供一个下一步操作；错误：说明影响、恢复路径、是否计费；不可用：解释缺少哪种连接。

## 05 · 每页完善点与验收清单

### 工作台
突出当前作品、最紧要的事实检查和待发布决策。推荐选题不是“所有 RSS 数据”，只显示经过初步筛选的候选并说明示例/真实状态。无需先创建系列或配置服务。

验收：点击继续直达当前作品；新建作品不超过两个主操作；空 workspace 仍可写作。

### 热点雷达（独立页面）
支持全部 / 与我相关 / 我关注的，多来源筛选与关键词查找。每行显示出现时间、趋势、平台、分类、原始出处；右侧/抽屉显示可信度边界、争议点和写作角度。实时生产端必须有来源链接、采集时间、源错误与合并记录。

验收：选中话题看到详情；一键收为候选跳转选题；关注的主题不会被自动变成文章，也不虚构热度指标。

### 选题发现
取消正面暴露大量简报字段；默认展示“读者问题、推荐切入角度、判断依据和证据缺口”。高级信息在详情可展开。AI 推荐既可以收藏观察，也可以明确放弃，不能假装证据充分。

验收：热点跳入选题后定位原候选，创作前可看到证据不足；一键进入作品。

### 作品库
同一篇内容可有主稿、公众号、知乎、配图、发布记录与复盘，首页按阶段可筛选，保留明确的状态定义。

验收：不同阶段准确筛选；打开作品能继续上次的平台与版本；重构不迁移出第二套文章存储。

### 创作空间
正文与 Agent 并存但不抢焦点。左侧大纲、中央可编辑文档、右侧上下文型 Agent。小屏先保证编辑内容，AI 结果可按需展开。顶部显示资料核查状态、平台稿独立标识、保存状态。

验收：主稿/平台稿 1 点击切换；自动保存、修订冲突、未采纳建议不覆写正文；没有 AI 时照常编辑；按单项视觉计划配图。

### 发布中心
公众号与知乎独立四项检查：事实与引用、隐私、版权、平台预览。显示交付时间线：待检查→可交付→草稿已创建/导出→报告实际发布→有依据地确认。不要使用同一个“发布成功”覆盖不同平台动作。

验收：检查未完成不能进入假成功态；中断后不重复推送；支持草稿箱回执和独立发布地址。

### 内容日历
周/月切换，日期点击选择查看内容计划；系列内容不要求强制周更，始终以当前工作节奏为准；后台 AI 调用应说明成本和授权。

验收：切换不会丢失选中日期；安排可以取消/变更；日历本身不执行发布。

### 效果复盘
数值必须来自可识别的真实账号/时间范围，不能混淆样例和真实统计。将反馈拆成“选题、内容质量、风格规则”。每条风格规则可查看依据和人工采纳状态。

验收：缺真实账号时显示空状态；无数据时不生成结论；学习建议须手动确认。

### 素材库
集中管理公开线索、文章引用、封面、内文图、历史文章与范文；支持搜索和分组。某条素材被移除时，要列出哪些文章或偏好依赖它。

验收：来源可追溯；可复用图片，但不将所有公开信息自动送入模型；删除/撤销留提示。

### 偏好与连接
优先显示账号画像与写作目标，再配置文本模型、图像模型、公众号/知乎、RSS、预算。关键授权提示出现在调用之前，不在每一页堆系统开关。

验收：密钥不上屏/不上日志；测试服务连接给出明确结果；无服务连接仍允许手写；切换模型不偷偷替换已排队任务的绑定。

## 06 · 典型状态与错误交互

| 状态 | UI 反馈 | 用户下一步 |
|---|---|---|
| AI 未连接 | “可继续手写；AI 功能待连接” | 设置中连接模型，非阻断 |
| RSS 失败 | 某信源显示最后成功时间、故障和重试 | 重试、停用或继续其他信源 |
| 事实待核 | 逐条说明是哪句话缺出处，不能只给一个总分 | 查看证据、补来源、标记观点 |
| 自动保存冲突 | 保留本地编辑与服务端修订，不自动覆盖 | 查看差异、保存副本或人工合并 |
| 任务中断 | 区分已调用模型、是否计费、是否有可恢复结果 | 查看结果/确认重试 |
| 图像生成失败 | 保留旧封面与正文；失败只影响当前候选 | 单图重试 / 换供应商 |
| 微信推送超时 | “发送结果待核对”，保留幂等键/任务日志 | 核对草稿箱后再决定是否重试 |
| 知乎手动交付 | 保留导出信息但不标记已经在线发布 | 填写链接或确认发布情况 |
| 没有统计权限 | 展示连接说明，不展示虚构增长结论 | 手动输入可验证数据 / 稍后连接 |

## 07 · 与现有仓库的实现衔接

已检查现有项目结构，设计对应关系如下。**这是未来开发映射，不代表本轮做了这些代码修改。**

| 原有实现 | V2.2 拟重构的入口 | 迁移要求 |
|---|---|---|
| `CreatorHome.jsx` + `CreatorShell.jsx` | 工作台与统一应用 Shell | 不再让编辑器跳入完全不同的导航体系 |
| `CreatorTopics.jsx` + 信源 API | 热点雷达 + 选题发现 | 热点与选题模型分开，但保留来源关联 |
| `WritingWorkspace.jsx` + `DoocsEditor.jsx` | 创作空间 | 保留 Markdown、自动保存、不可变修订和差异审阅 |
| `IllustrationStudio.jsx` + 图像资产服务 | 作品内配图工作区 | 独立选图、替换、生成与原文版本关系 |
| `PublishingControls.jsx` + 发布适配器 | 发布中心 | 区分导出、草稿与真实发布；保留四项检查 |
| `CreatorLibrary.jsx` | 素材库 | 显示素材来源和引用链 |
| `CreatorSettings.jsx` | 偏好与连接 | 将模型服务/账号/预算从日常创作 UI 中后移 |
| `StudioApp.jsx` | 不作为新版 Creator 主界面 | 若旧页面仍存在，仅作迁移期兼容，不再叠加功能 |

实施建议：先完成统一 Shell + 作品主路径，再完善热点与选题，再改编辑器外壳，随后是发布、配图、日历和复盘。上线前执行桌面/移动端真实 E2E、数据兼容、真实服务调用、账号授权与 Dokploy 构建检查，不能仅用本原型声明上线可用。

## 08 · 本版原型已验证的交互与限制

- 已验证：十个桌面页面和十个手机页面渲染；横向无溢出（393px 与 1440px 测试宽度）；热点点击进入移动详情；热点转选题；作品进入编辑；主稿/平台版本控制外观；配图样式切换；发布核查勾选；日历周/月切换；复盘时间段切换；素材集合过滤；移动底部导航。
- 所有文本数据、趋势、平台统计、更新日期、发布状态、文章和 AI 建议均是**展示用示例**。按钮效果可能只在当前原型会话生效，不写入数据库，不调用外部服务，不产生模型费用。
- 原型为单个离线 HTML 文件；在某些聊天客户端不能直接预览 HTML，可打开 PNG 页面预览或将文件保存到本地浏览器。
- 没有做真实模型/平台/API/部署兼容性验收，也没有提交 GitHub PR。
