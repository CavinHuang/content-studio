# Content Studio · Creator V2.3

## 文章 AI 配图助手与独立视觉工作台 · UI/UX 设计规范

版本：V2.3 / 2026-10-19  
范围：Creator V2.2 的配图体验专项设计；**交互原型，不包含真实 API、用户数据或生产部署**。

## 0. 产品决策

产品不是“让用户管理出图工具”，而是“让用户为文章补充真正有用的视觉内容”。以 **文章/作品** 为唯一上下文入口，配图的最小单位是**与正文版本和段落锚点绑定的视觉意图（shot）**。

Easel 可借鉴之处是独立的文生图、图生图、变体、裁切与素材能力；WeWrite 可借鉴之处是先理解文章、只为必要段落配图、统一风格、控制费用和保持文字原稿不被覆盖。Content Studio 现有后端已经具备大量相关能力，所以 V2.3 聚焦**统一交互与前端编排**，不是第三套图片数据库或重复造 Agent。

## 1. 页面结构

### A. 文章中的「AI 配图助手」

三栏桌面版：

- 左：文章大纲、配图定位，文字状态与引用提示；
- 中：正文为主，每处配图以**内联插图槽位**表示。已采用图直接展示缩略图；待生成图显示明显但不打断阅读的占位；
- 右：从上到下是模式切换（只做封面 / 完整配图 / 指定段落）、Agent 推荐方案、选点与风格、费用授权、生成、逐张审阅。

原则：打开配图助手时，第一屏必须回答 **配几张、插在哪里、为什么需要**，不应是供应商和 Prompt 表单。配图规划应先于任何费用调用；模型与重试上限放在高级设置，生成前的授权确认必须可见。

### B. 独立「视觉工作台」

三栏桌面版：

- 左：本作品配图清单，状态分为待规划、待生成、待审阅、已采用、失败、过期；每一张都可精准定位回文章；
- 中：当前候选大图、方案版本画廊、双图对比、选择候选与采用；
- 右：图片意图、段落锚点、统一视觉风格、自然语言改图、图片加工工具、模型成本高级设置、Alt 文本与 QA 状态。

视觉工作台只编辑当前作品的图片，不承担跨文章素材库的所有功能。已采用图片进入文章；原图/候选/采用版本同步关联素材库。

### C. 阅读预览

在配图页面任何位置可进入阅读预览，先切换公众号 / 知乎，再显示**已采用**的图片，不展示纯候选。预览不代表真实平台验收；需要保留裁切、外链、版权和图片可用性检查。

## 2. 核心操作路线

```text
正在写文章
   ↓
点击 AI 配图 → 先读到配图建议（数量/位置/原因）
   ↓
切换：只做封面 / 完整配图 / 指定段落
   ↓
保留/取消具体段落，确定风格（默认继承作品/系列）
   ↓
生成前确认：所传内容、供应商、图数、金额估算
   ↓
独立生成每张图，保留成功与失败记录
   ↓
视觉工作台：切换候选 / 对比 / 修改 / 重生成 / 检查
   ↓
明确“采用这张图” → 对应文章位置可见
   ↓
公众号/知乎预览 → 平台级检查与交付
```

关键状态：**选中候选 ≠ 已采用**。点选缩略图只改变预览，点击“采用这张图”才提交 article-slot→asset-version 的关系。修改或生成变体必须保留旧版本，不默默替换文章。

## 3. 核心组件和交互清单

| 组件 | 必须实现的反馈 | 禁止行为 |
|---|---|---|
| 配图模式切换 | cover / full / selection 对应不同位置和默认数量 | 切换模式时自动调用付费模型 |
| 配图规划卡 | 显示为何需要、段落锚点、形态、比例及可取消选择 | 强制每个标题后插图；凭空编造图表事实 |
| 风格选择 | 锁定账号/系列调性，预览色板，可在单张覆盖 | 后台静默更换已采用图 |
| 生成确认 | 图片数、Provider、成本预估、传输范围、异常费用提示 | 默认勾选高费用动作 |
| 单图候选版本 | 可切换、比较、查看历史、单张重试 | 一张失败导致整个批次无法审阅 |
| 自然语言改图 | 默认针对当前版本，保存新版本，清晰提示变更范围 | 覆盖原图；影响其他插图 |
| 采用 | 明确提交、即时回写文章定位、可继续替换 | 仅切图就写入已审阅正文 |
| 阅读预览 | 只显示已采用图；切公众号/知乎；提供最终 QA 入口 | 把模拟预览标作平台实际发布成功 |
| 移动交互 | 正文/配图规划/选图编辑底部切换，单栏内容，触达关键 CTA | 手机屏幕同时强塞三栏或显示大量模型设置 |

## 4. 错误状态与安全边界

1. **主稿已变化**：旧配图计划仅能查看历史，禁止无提示复用旧段落锚点；提示重新规划并保留旧图。
2. **供应商 429/超时/失败**：记录图片级状态、计费不确定性和可重试动作；成功图片继续可审阅。
3. **异步任务中断**：不能宣称生成成功或自动重发收费请求；显示“结果待核对”。
4. **费用授权**：UI 展示使用哪家图像服务、预计张数与总价/上限；模型费用只是估计时明确注明。
5. **截图/事实**：不能凭空生成“真实产品界面截图”“图表里的未经验证数据”。大量汉字、流程、参数、表格优先使用确定性 SVG/HTML 排版。
6. **图片版权、来源与隐私**：任何参考图进入外部模型前需显示将发送的素材，确认后才发；第三方资产不自动当作可再发布素材。
7. **导出 ≠ 发布**：内容状态分开追踪设计完成、上传、平台草稿、已真实发布、外部反馈。

## 5. 默认布局规范

- 继承 V2.2：深色产品导航 `#222635`、暖灰白内容背景、靛蓝主操作 `#4763DB`；保留小而有识别度的状态色。
- 文稿阅读宽度优先；不要为小型审阅控件压缩正文。高级信息默认折叠。
- 主 CTA：在助手中为“生成选中的图片”；在视觉工作台中为“采用这张图”。避免一个页面出现三四个同权重按钮。
- 图像尺寸示例：公众号封面以约 **2.35:1** 为目标、正文横图以 **16:9** 为常用选项。具体 API 输出尺寸可能不同，最终需在加工阶段裁剪/补边并核对平台。
- 桌面：编辑器以 `大纲 / 文稿 / Agent` 三栏组织，视觉工作台以 `配图位置 / 候选图 / 修改控件` 三栏组织。
- 手机：小于 760px 时，编辑器转为 **正文 / AI 配图助手** 两个单页状态；底部固定 **正文 / 配图规划 / 选图编辑 / 预览**。视觉工作台顶部横滑切换配图位置，候选和工具上下排列。

## 6. 与现有 Content Studio 代码的衔接

| 已有实现 | V2.3 的处理建议 |
|---|---|
| `components/WritingImages.jsx` | 保留原 API 契约，把原有按钮/检查框/列表重构为文章侧边的规划模式与槽位结果；不要新增存储层。 |
| `components/IllustrationStudio.jsx` | 作为独立视觉工作台的主要页面能力来源；拆出候选、修改、采用、验证等纯视图组件。 |
| `components/IllustrationQueueWorkspace.jsx` | 保留持久队列、预算/中断/恢复机制；前台显示「进行中/完成/失败」而非直接暴露队列协议。 |
| `src/illustrations.mjs` | 沿用原 shot ID、文章修订、审核、媒体映射约束，必要时增加“候选与采用版本”读模型。 |
| `src/image-providers.mjs` | 保留 OpenAI、Gemini、Qwen provider 适配，UI 默认自动选择，可在高级设置切换。 |
| `components/VisualSeriesPanel.jsx` | 将“风格锁定/系列复用”提成直接可理解的风格选择，不要在文章配图首屏展示完整系列权限管理。 |

需要特别留意当前 `WritingImages.jsx` 使用顺序 `for...of` 逐张调用生成 API，若没有图片级失败隔离，一张错误会打断后续图片。建议优先复用持久队列，把失败、重试和结果回收按图片独立展示。

## 7. 建议实施顺序与验收

**P0 · 先让配图真正好用**：统一从作品进配图、明确数量与段落、可生成、可逐图审阅、采用后正确插入，并能回到文章与预览。

**P1 · 提升制作效率**：单图自然语言编辑、候选版本比较与替换、跨文章视觉风格复用、参考图，以及异步图片级任务恢复。

**P2 · 专业制作**：裁切与多平台比例联动、SVG 数据图模板、视觉质量检查与 Alt 文本建议、批量导出。

功能验收应覆盖：已有主稿 / 修改中的主稿 / 没有图像服务 / 部分图片生成失败 / 用户中断 / 旧计划失效 / 微信平台独立审稿 / 移动单手操作。生产验收必须通过真实 Provider、浏览器和平台稿检查；静态原型不能证明这些。

## 8. 原型测试说明

HTML 为自包含 Demo：所有图片使用本地嵌入 SVG 视觉示意，不需要网络或 API Key。能够进行配图模式切换、批次确认、产生模拟候选、切换版本、版本对比、自然语言改图演示、采用图片、回到正文与平台预览。按钮不调用外部模型，不产生真实账单，也不向 GitHub 推送。

本轮浏览器检查：桌面 1512px、手机 390px，无横向溢出；测试覆盖版本对比、采用、预览渠道切换、完整配图模拟、移动版切换。
