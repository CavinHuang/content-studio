## 0. 设计产物保真验收（必须先执行、逐页结论）

**参考源：** \`public/design/creator-v2.2.html\` 是全站设计主标准；\`public/design/creator-v2.3-visual.html\` 是配图交互主标准；\`public/design/assets/creator-v2-tokens.json\` 与 SVG 是可编辑视觉资产。设计 JSX 预览是辅助示例，不能替代两份原始高保真 HTML。生产功能必须复用真实 API。

| ID | 验收标准 | 所需证据 |
|---|---|---|

| V04 | 手机 390×844 完成原型对应交互；全局导航与创作内部导航不混用，热点详情/图像比较/配图规划/返回文章可操作 | 手机原型与真实页面并排截图 + E2E |

## A. 工作区一致性

| 编号 | 可验证结果 |
|---|---|
| A01 | 所有正式 Creator 页面有统一侧栏、标题区域、操作样式，主导航突出当前页，不与旧 StudioApp 的视觉/导航混用 |
| A02 | 热点雷达为**独立一级页面**，不是藏在选题页面的一个 tab |
| A03 | PC 1440×900 布局能显示主要内容和操作，390×844 手机可以完成主流程，侧栏和更多菜单可使用 |
| A04 | 移动端正式路由无横向溢出；键盘焦点和按钮语义正常，不存在只有 hover 才能操作的内容 |
| A05 | 网络等待、首次空态、401 登录过期、403 禁止、409 修订冲突、500/503 错误有不同可理解反馈和重试路径 |
| A06 | 真实业务页面不出现硬编码示例热点、假阅读数、假图像、假成功、无效 CTA 或把“模拟”写成“运行中” |

## B. 热点 → 选题 → 作品

| 编号 | 步骤与期望 |
|---|---|
| B01 | 用合成 RSS/来源记录创建可用信源；热点展示真实 source-item title、来源与时间；没有 timestamp 则不编造 |
| B02 | 筛选信源、搜索关键词、点击详情、打开原文链接，结果来源可追溯 |
| B03 | 点击「收为选题候选」，创建有来源的真实选题记录；刷新仍在、重复转化有提示 |
| B04 | 选题页从该候选回显标题、现有来源及证据缺口；保存和重进后不丢 |
| B05 | 点击「开始写作」生成真正的 project id，并打开相应`/compose?project=...`；新建和直接创作同样有效 |
| B06 | 选题推荐使用真实受权数据；无 AI 配置/未授权时可退回本地研究或清晰说明不可用，绝不发送私有正文 |
| B07 | 没有可比的历史时间序列时，不出现“上升 90%”等模拟热度/来源交叉验证标签 |

## D. 图片规划 → 生成 → 审核 → 采用

| 编号 | 步骤与期望 |
|---|---|
| D01 | 在实际作品内切换封面/全文/指定段落，能基于真实主稿修订及段落标识建立计划 |
| D02 | 在点击付费生成前，能读懂预计次数、服务、传输数据范围并明确同意；未同意不触发调用 |
| D03 | 未配置图像服务时，仍能查看非付费配图建议/提示词，不出现假图片或假“生成完成” |
| D04 | 视觉工作台能直达指定 project+slot，显示真实图位、Prompt、候选、状态和错误 |
| D05 | 仅单击候选版本时，不改变 approve/insert 记录，也不修改任何稿件；切回来仍可识别正在预览的版本 |
| D06 | 使用合成 provider 生成两张：分别记录、显示候选；一张故意失败，不取消其他成功结果 |
| D07 | 单张改图保留原始版本且不改变未修改图位；失败或网络中断保留历史和可恢复状态 |
| D08 | 点击「采用」才经现有权限、expectedRevision、批准/插入流程修改目标；刷新后仍有真实映射，不能只保存在 React state |
| D09 | 若主稿在计划建立后变化，旧图计划明确提示过期，拒绝复用旧 approval/插入，保留旧素材供审查 |
| D10 | 预算不足、队列中断、超时、单张重试、重复点击不突破额度或无限向模型重发 |
| D11 | 公众号与知乎各自的交付/图片 URL 状态真实；未真正上传 CDN 的图不能显示“平台已验证” |
| D12 | 手机上能完成配图规划、对比、采用、返回正文；没有三栏拥挤、弹窗不可关闭或视口外按钮 |

## F. 可靠性与 QA

- `npm ci --no-audit --no-fund`：结果和 Node 版本记录在 QA。
- `npm run check`：通过（或标记真实基线故障与对照证据）。
- `npm test`：全部现存单测和新增单测通过。
- `npm run build`：通过现有 V63-V76 原生构建保护，不绕过。
- `npm run test:e2e`：全量浏览器 E2E 在真实 Next 应用和合成数据上通过。
- 新增/更新 Playwright：每条 B/C/D 关键流至少有可复现验证；必要处使用真实本地路由和假 provider，不发送远程付费请求。
- 对全部正式 Creator 路由执行 390px 手机 overflow 审计，保留至少首页、热点、创作、视觉工作台、发布的桌面/移动截图。
- 对失败场景收集准确日志、失败 trace / 截图，并且修复选择器歧义，不能靠跳过或注释测试获得绿灯。
- 保留现有登录认证、CSRF、私有数据隔离、构建校验、发布授权检查与编辑器修订语义。
- 真实公网平台发布、CDN 粘贴、生产 Dokploy、私人备份恢复等未获凭据/权限的项目标记**未验证**，不伪造通过。

## PR 合并准备完成定义

必须存在：
1. 真实产品路由（非 design 预览）；
2. 与原 API/数据库的端到端实现；
3. 所有 P0 + P1 页面基本可用；
4. 完成矩阵逐项有证据；无空泛“已实现全部”；
5. 实现 PR 是 Draft/待评审状态，未自动合并、未自动生产部署；
6. 问题仅保留可复现且确实需要用户权限的硬阻塞，其他修复在同一个开发任务中闭环。

如某条不具备可靠数据来源，则应明确呈现真实空状态并在矩阵中解释，该条不能通过模拟“成功”满足。
