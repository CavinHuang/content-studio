# V1 创作产品使用与实现

本轮把产品基线中的业务路径接入 Next.js 主界面。入口为首页 `/`、选题 `/topics`、创作 `/create`、资产库 `/library`、创作者设置 `/settings`。单篇工作台仍为 `/compose?project=…`，旧排版交接留在 `/compose/handoff`。

## 先使用一条完整路径

1. 在设置填写领域、读者、目标、语气与视觉偏好，配置写作 / 配图服务。支持 OpenAI 兼容接口，API Key 在服务端加密，不回传到浏览器。
2. 在资产库添加自己的笔记、Markdown / TXT / CSV / JSON 文档、公开链接或图片。在设置中可订阅公开 RSS / Atom。
3. 在选题页记录想法，从现有信源发现候选，或明确选择允许参与推荐的私有素材后授权模型推荐。与助手讨论，补全核心问题、观点、证据缺口、大纲、目标读者和目标平台，审阅并采纳简报后开始写作。
4. 在集成的 doocs/md 编辑器里输入、讨论、生成初稿或选区改写。AI 建议接受前不改动正文；自动保存、历史恢复和并发冲突处理使用同一篇文章的修订系统。
5. 配图助手支持全文 / 指定段落规划、独立费用授权、候选审阅与插入。上传的图片和生成结果都进入本地资产库。
6. 主稿、微信公众号、知乎、小红书稿独立保存。公众号 / 知乎可继续 Markdown 编辑、复制排版或下载文章与图片包；公众号账号通过能力检查后，可显式发送到草稿箱。
7. 小红书先规划标题、正文、话题与分页，确认独立文案，再生成实际 PNG。可自然语言改单页 / 拆页 / 调整整组风格、重排、恢复图组历史。每次图组修订后重新检查；下载包含 PNG、文案和带哈希的版本清单。
8. 实际发布后记录链接；资产库查看交付事实、人工阅读 / 点赞 / 评论及复盘。文章、素材、图片可再次成为新选题的来源。

## 作者账号与隔离

为了兼容现有本地单人数据库，默认仍可使用原本地工作空间。启用作者账号：

```sh
CONTENT_STUDIO_MULTIUSER=1 npm start
```

也可在私有运行配置中持久设置。`CONTENT_STUDIO_ACCOUNTS_PATH` 默认是 `CONTENT_STUDIO_DB_PATH` 的目录；该目录必须为当前进程私有的 `0700` 真实目录。不要把它指向公开、共享或软链接目录。

每位作者使用独立 `workspaces/ws_…/studio.sqlite`。所有新旧 API 在选择 core 之前校验登录，因此旧资源 ID、图片预览、搜索、队列、核查和导出也由同一作者边界保护。注册不会自动认领旧数据库。

账号密码使用 scrypt；会话是服务端保存摘要的随机令牌，8 小时有效，退出即撤销。远程模式使用 `__Host-` Secure / HttpOnly / SameSite=Strict Cookie。原有同源 JSON / Host / Origin 检查继续执行。多作者模式不改变默认 localhost 绑定；Dokploy 模式仍须满足原 V75 的 HTTPS、代理与运维配置。远程注册默认关闭，只有 `CONTENT_STUDIO_REGISTRATION_OPEN=1` 才开放。

这是单进程持久 SQLite 应用。当前最多同时打开 100 个作者 core；不支持横向多实例同时写入、Edge 或无状态 serverless。新账号和业务库需要纳入同一私有持久卷。

## 旧库归属与迁移

迁移必须离线进行，先注册明确的接收作者，保持接收工作空间为空。工具创建新的 V45 WAL 安全备份与 manifest，再恢复到该作者新数据库，并逐行 / BLOB 比较；原库和备份均保留。任何已有作者库都会拒绝覆盖。

```sh
npm run author:import -- \
  --source=/absolute/private/legacy.sqlite \
  --accounts-root=/absolute/private/accounts \
  --author-email=owner@example.com \
  --backup=/absolute/private/backups/new-archive.sqlite
```

如果旧库包含加密连接，原 `.services.key` 必须可用且权限为 `0600`。迁移会将凭据重新加密到作者账号密钥，并在私有备份目录保存凭据密钥备份。不要通过日志、网页或 Git 传递密钥。

## 系列与画像学习

系列保存目标、篇目顺序、准备间隔、时区、下一次准备时间、后台 AI 授权和运行状态。服务端 instrumentation 每 3 秒检查一次持久任务；关闭页面不影响调度。每次仅准备下一篇的简报、大纲与材料。暂停 / 调整中的旧模型结果会被丢弃。任务使用去重键与租约，中断任务标记待核对，不自动重复计费。

准备任务保存入队时的选题、系列、画像和所选素材快照。同一系列的待执行任务会去重；旧执行者在任务被核对后不能写入迟到结果。“需要处理”和“中断，结果待核对”的任务可以在选题页的系列面板中填写核对依据，然后取消或显式重试。重试保留原任务记录并建立新尝试，调用模型前须重新授权费用；未知费用仍须在设置的用量页核对。系列或选题已修改时，应取消旧任务，再按新计划准备。

模型任务固定入队时的连接及配置指纹，切换默认模型不会更换已排队任务的服务。连接被修改 / 删除、平台默认凭据改变或旧任务缺少绑定时，须在任务核对中明确重新绑定。每次准备、学习和写作生成尝试最多发送 1 次模型请求，并继续受每日额度约束（该上限约束非 agent 的单次生成路径；agent 运行见 [AGENT-V1.md](AGENT-V1.md)：多步循环、v1 不设请求数上限、逐次记账并受每日额度约束）。失败或费用结算不会恢复该尝试的请求次数；作者确认的重试是新尝试。这是请求数上限，金额与 token 账单仍以服务商为准。

公开信源启用即授权每小时读取其公开 HTTPS RSS / Atom，记录最近执行时间和状态。URL 导入与信源读取均使用全地址公网 DNS 校验、TLS 校验、固定解析地址、响应大小 / 时间上限和禁止跳转。

画像支持显式偏好、本篇覆盖、平台覆盖、历史恢复和学习暂停。手动选择文章提炼风格；也可单独开启“发布后后台学习”的持续授权。推断保存文章修订、哈希与写作反馈来源，先进入待审建议，确认后才写入新画像版本；不会自动改写画像或执行发布。

后台学习固定读取入队时的文章修订，不混入之后的修改。作者可“修订后采纳”，原模型建议、来源和作者确认的文本分别保留；移出建议列表不删除已应用画像或历史版本。学习授权在调用期间撤销时，返回结果不会进入建议。

## 流式预览与逐项采纳

写作助手可逐段预览模型结果，预览与正文分开保存。停止、断流、超时或服务返回不完整结果时，保留未完成记录和部分文字，正文保持原修订。历史入口可下载部分结果，或载入原要求重新生成；重新生成需再次确认费用，创建新请求，不会自动续发。恢复时仍检查文章、上下文和原连接版本。服务不支持流式响应时，可主动关闭“逐段预览”；失败不会隐式切换方式并再次计费。

一次模型结果可包含最多 12 处不重叠修改，分别审阅、接受或拒绝。接受一处会生成文章新修订，并调整同一批其余建议的位置；原建议的来源修订仍保留。手动编辑、其他批次写入或上下文变化会使旧建议失效，避免错位覆盖。讨论结果与未完成生成均不能直接作为修改接受。

## 账号定位与来源移除

在设置中可为每个发布账号保存定位、读者、语气、结构、避用表达、篇幅与视觉偏好，空字段继承作者画像。在创作上下文中明确选择对应平台账号后生效，优先级为作者画像 → 账号偏好 → 本篇偏好 → 本篇平台偏好。账号设置更新保留版本，旧写作授权和建议不能覆盖新偏好；不会自动改写已有文章。

资产库的“移除来源”先展示关联文章、风格建议及当前画像字段的影响范围，再由作者确认。预览后关联关系或画像变化，必须重新预览。素材移除会清空当前正文、链接、标签并归档；文章移除表示停止作为学习来源，文章正文及不可变修订保留。相关引用在后续上下文中不可用，须移除或排除后再生成。

系统撤销相关风格 / 写作建议、停止相关任务和生成，并禁止受影响文章继续学习。当前由这些来源推断的画像字段回退到安全版本，作者另行明确改写的偏好保留。历史界面隐藏已撤销的推断及证据，不能恢复失效画像。修订后采纳的风格建议仍保留来源关系。此操作处理当前来源及其推断关系；不可变文章历史、数据库空闲页及既有备份不属于安全擦除范围，确认界面会说明。

## 简报、创作上下文与资产筛选

简报修改生成新版本，历史恢复也创建新版本。收藏 / 暂不创作可填写原因，这些反馈与历史文章标题、系列计划共同用于后续推荐。AI 推荐默认不发送私有素材正文，只有勾选的素材可进入请求；推荐界面同时说明会发送的画像、标题、系列和反馈。

讨论建议绑定产生建议时的简报版本，旧建议不能覆盖新简报。写作建议同时绑定文章、简报、画像和创作上下文版本；任一来源变化，都需要重新生成建议。不同渠道共享文章级素材与本篇偏好的版本检测，防止两个页面相互覆盖。发生冲突时保留页面本地选择，作者可查看并重新载入服务端内容。上下文 API 的 PUT 请求必须传入 `expectedRevision`，从 GET 返回值取得，首次为 0。

写作助手中的“本次将发送的画像与素材”列出当前画像、简报和上下文版本、有效偏好、所选素材及已排除数量；原始选题信源单独展示。请求还包含当前文章、写作要求和近期讨论摘要。另一个页面改变上下文后，旧授权请求会在模型调用与额度预留之前被拒绝；刷新后需要重新勾选授权。生成结果保存来源名称、文章修订和偏好快照，可从“生成时使用的上下文”复核，之后的画像更新不会改写旧记录。

公众号 / 知乎稿提供“查看并合并主稿差异”。它对照平台稿上次确认的主稿版本、当前平台表达和最新主稿，逐处展示修改。可勾选没有重叠的修改，保留平台自己的表达；同一处已由双方修改时，必须明确选择保留平台表达，再按需在编辑器手动调整。相同修改不会重复插入。大段变化使用保守的整段对比，不能安全合入时不自动覆盖。

确认后保存新的平台修订与逐项选择记录，并更新已审阅的主稿版本，四项发布检查重新开始。主稿、平台稿或审阅内容发生变化时返回冲突，不写入旧审阅。平台版本历史显示本次来源主稿版本及合入 / 保留数量；既有历史和其他渠道保持独立。首次完整适配仍可使用“从主稿创建新版本”；小红书由图文规划流程适配，不使用文字段落合并。

资产库支持系列、关联平台、创建日期范围和现有类型 / 标签 / 文字组合筛选。日期按北京时间，结束日包含当天。平台关联包含实际编辑的平台稿或交付事实，不等同于已发表；系列关联也涵盖该系列文章使用的参考素材和图片。

## 小红书成品与发布语义

图组使用固定 ID 和不可变修订保存文案、场景、布局、颜色、输入资产、模型 / 提示、实际 PNG 和检查报告。内部由 sharp / SVG 合成精确中文文字，使用 Noto CJK 字体；当前交付规格为 1080 × 1440，并非宣称平台永久规格。

图片生成前需要确认平台文案。单页修改只替换指定页，其他资产哈希不变。仅修改文字时保留已生成背景；勾选新视觉并确认费用后才重新请求图片服务。分页、重排、整组风格调整与历史恢复均生成新图组版本。四项检查绑定准确图组修订和渠道修订；主稿变化也会阻止旧方案继续导出。检查报告包含文字边界、尺寸和文字哈希，仍需作者核对事实、权利和实际裁切 / 显示。

平台账号与媒体映射按作者数据库、账号、资产和用途隔离。公众号适配器固定请求 `api.weixin.qq.com`，token 加密缓存；封面 / 正文媒体分开处理。当前适配仅支持本地 PNG / JPEG 媒体，发送前拒绝未经审阅的正文外链图片。准备媒体期间稿件变化会阻止正文发送。

幂等键与同账号同修订去重防止重复发送；正文请求中断后标记 `outcome_unknown`，作者在平台核对并填写依据后才能结算。不会自动重试未知结果。

操作状态与交付事实分开：

| 事实 | 证据 | 含义 |
| --- | --- | --- |
| exported | local_export | 生成本地交付包 |
| draft_saved | provider_response / author_report | 官方接口回执或作者核对草稿 |
| published | author_report | 作者实际发布后填写链接，未经平台核验 |

**真实外部验收尚未完成：** 当前云环境未配置可用模型 / 图片 / 公众号测试账号，官方文档域名访问此前被代理返回 403。自动测试使用明确标记的合成模型和公众号协议回包；不代表真实平台成功。知乎 / 小红书未假设存在通用官方发布接口，当前通过复制 / 成品包 / 人工回填交付。公众号适配器需在有权限的实际账号上复核现行文档、IP 白名单、媒体限制和草稿写入回执。

## 存储、额度与运行

`authors.sqlite` 保存身份和会话；`authors.key` 为 `0600`。作者库保存业务、原有证据模型、Markdown sidecar、图片 BLOB、加密连接和平台凭据。单人模式凭据密钥为数据库旁的 `.services.key`。备份必须同时保护数据库和对应密钥，丢失密钥不能恢复连接。

额度按 UTC 日统计（北京时间 08:00 重置），与系列的计划时区独立。每次模型 HTTP 请求先预留每日调用额度，分别记录文字 / 图片、成功 / 失败 / 未确定状态和可用 token 用量。单位是请求数，金额不估造，账单以服务商为准。未知结果占用额度，作者核对后结算。原配图 V38 预算继续保留。

生产构建继续走 V50 guard 和 V64 / V65 封存。使用 Next Webpack 构建，避免 Turbopack 为原生图像依赖产生符号链接；没有放宽 V64 的链接拒绝规则。Docker 运行层新增 Noto CJK 中文字体，字形缓存使用进程私有 `/tmp` 目录，仍支持只读 rootfs。

测试和实施状态见 [CREATOR-V1-QA.md](CREATOR-V1-QA.md)。
