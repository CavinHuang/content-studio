# 平台官方文档调查（文档级）

日期：2026-10-17。对应 [PRODUCT-IMPLEMENTATION-PLAN.md](PRODUCT-IMPLEMENTATION-PLAN.md)「外部验证结果与待办」中"后续接入 spike 需读取现行官方文档"的文档读取部分。

**边界声明：本轮只做公开文档阅读，未注册账号、未获取 token、未调用任何平台接口。** 下述事实仅代表官方文档当前文字，不等同于实际账号权限、真实回执或发布成功。所有真实账号验收（IP 白名单、参数限制实测、草稿回执、频次限制实测）仍为待验事项。

## 微信公众号

此前云环境对官方文档域名的出站访问曾被代理拒绝（403）；本轮从当前工作环境可直接读取 `developers.weixin.qq.com`。以下为已读取页面的要点。

### access_token（全局接口调用凭据）

- 公众号各接口调用的全局唯一凭据；存储需预留至少 512 字符空间。
- 有效期当前为 2 小时，需定时刷新；重复获取会使上一次获取的 token 失效。
- 官方要求集中刷新并全局共享，避免并发刷新互相覆盖。现行代码（`src/publishing.mjs`）以加密缓存实现单进程内集中管理，与该要求一致；多实例部署下需独立的集中刷新机制（当前单进程持久 SQLite 部署形态不涉及）。

### 草稿箱 draft/add（新建草稿）

- `POST https://api.weixin.qq.com/cgi-bin/draft/add?access_token=ACCESS_TOKEN`，与现行适配器固定 host 的做法一致。
- 请求体为 `articles` 数组，每篇字段包括 `title`（≤64 字）、`author`、`digest`（留空时默认取正文前 54 字）、`content`、`thumb_media_id`（必填）、`need_open_comment`、`only_fans_can_comment`，以及 `pic_crop_1_1` / `pic_crop_2_35` 等封面裁剪字段。
- `content` 为正文 HTML：支持 HTML 标签、去除外链 JS、少于 2 万字符、小于 1MB；**正文图片链接必须来自官方"上传图文消息内的图片获取 URL"接口（`media/uploadimg`），外部图片 URL 会被过滤**。
- `thumb_media_id` 必须是**永久素材**的 MediaID，即封面需先经 `material/add_material` 上传，不能用临时素材。
- `article_type` 支持 `news`（图文）与 `newspic`（图片消息，最多 20 张图）。
- 成功返回 `media_id`（草稿 id，≤128 字符）。草稿可被官网后台与后续接口修改/删除。

### 正文图片 media/uploadimg

- 用于图文正文内图片，返回可直接嵌入 `content` 的 URL；与封面所需的永久素材（`material/add_material`）分开，与现行适配器"封面 / 正文媒体分开处理"的设计一致。（该页正文本轮仅部分返回，具体额度与尺寸限制待真实账号复核。）

### 发布能力 freepublish（存在，但本产品不自动调用）

- 官方提供草稿发布接口（`freepublish/submit`、状态查询 `freepublish/get`、删除 `freepublish/delete` 等）：把草稿箱中的草稿发布为正式内容。
- 文档明示：**2025 年 7 月起，个人主体账号、企业主体未认证账号及不支持认证的账号被回收上述发布接口的调用权限**。即自动发布路径依赖已认证账号。
- 本产品的既定领域边界（AGENTS.md / PRODUCT-V1）是**导出与草稿箱成功不得产生 published 事实；真实发布由作者人工执行并回填链接**。这是产品决策：平台存在发布 API 不改变"export != actual publish"的不变量；V1 适配器只到草稿箱为止。上述账号权限限制进一步降低了自动发布的可依赖性。

### 真实账号验收仍缺（不变）

- 公众号类型与权限（草稿箱能力对账号类型的适用范围）、AppID/secret 凭据、服务器 IP 白名单配置、频次限制实测、真实 `media_id` 回执与草稿官网显示核对。

## 小红书

- `open.xiaohongshu.com` 当前可访问，首页显示为**电商开放平台**（面向电商商家 / 开发者的控制台、文档中心、服务市场）。
- 从该入口未见面向个人创作者的笔记发布 API 说明。若存在面向专业创作者的内容开放能力，需要开发者控制台 / 商务合作渠道进一步核实，本轮无法确认。
- 与设计一致：知乎 / 小红书当前实现复制排版、图文交付包与作者人工发布回填（`author_report` 证据），不假设通用官方发布接口。

## 知乎

- `open.zhihu.com` 本轮仍无法程序化读取（网页读取工具网络错误；HTTP 抓取返回 422）。403/422 仅证明当前无法读取，不证明平台不提供 API，也不证明账号缺少权限。
- 该入口的产品适用性继续标记为**未核实**。

## 结论

- 公众号草稿箱路径的官方文档事实与现行适配器形状一致（固定 host、token 集中缓存、封面永久素材与正文图片分离、幂等发送）；接入 spike 的剩余阻塞全部在真实账号侧，文档读取部分已完成。
- 小红书维持交付包 + 人工回填路线；知乎入口仍不可及。
- 本文件仅记录文档事实与可及性，不构成任何真实平台验收，也不产生 merge/deploy 授权。
