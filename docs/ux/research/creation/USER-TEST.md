# 创作者试用与产物盲评材料

状态：尚未开展，未联系参与者。由项目所有者邀请目标创作者；联系渠道和参与授权待提供。程序对照记录不填写本研究结果。

## 参与方式

选择实际会使用工具的独立创作者，覆盖新手与熟练者。首轮用于发现问题；样本量不作为统计显著性的保证。正式量化试验根据先导数据决定样本量。参与者可拒绝录屏；采用匿名编号，未经允许不采集账号、私密文稿或凭据。

## 给参与者的任务

“你有一个主题和几条未整理的记录。请用这个工作台整理成一份你愿意继续编辑的底稿，做一次自己的校订，然后下载 Markdown。完成后请指出哪些地方仍然不能使用。”

不告诉用户去哪个页面、应该点哪个按钮。主持人不代操作；协助算作有帮助完成，单独记录。判断是否完成依据实际下载与参与者能否继续编辑，不依据页面上是否显示成功。

每位参与者使用两份难度相当但内容不同的素材，交叉安排旧路径和新路径，避免同素材重复使用的学习效应。一半先旧后新，一半先新后旧。试用材料须包含作者经验、未核验链接、一个无法直接推导的结论；不要把替代任务变成填写已准备好的方案。允许用户选自己的非敏感真实记录，取得许可后保存原始版本和修改痕迹。

合成先导素材 A：

主题：少收集一点，给每周回顾留出时间。

记录：周五原始记录：我存了 12 个链接，只重读了 2 条。下周先重读，再决定要不要继续收藏。

合成先导素材 B：

主题：先写散步观察，再考虑拍照。

记录：周三散步 20 分钟，拍了 8 张照片。回家只记得街角的面包香。下次先写两句话，再决定拍什么。这个体验只来自我自己，不能代表所有人。

## 观察与计时

从看到任务材料开始，到实际下载完成结束，分别记录总耗时、系统等待、查找、阅读核对、编辑与恢复。记录鼠标点击、快捷键、输入次数及字数，区分粘贴和键入；同时记录跨页、重复说明、实质创作决策和流程确认。不要用脚本 fill 次数冒充键击。

发声思考会改变耗时：探索研究可以发声，正式计时另做安静完成任务。失败、放弃、求助和中断均保留，不从时间统计中悄悄删除。按事先口径区分独立成功、有帮助完成、部分完成与失败。

安排一个自然纠错任务：生成期间改变主题、正文手改后准备新候选，或关闭后继续。记录找回输入、识别旧候选、恢复正文的操作和用时。观察“停止”是否被理解为丢弃输入。

结束每个版本后，让用户填写相同版本的 NASA-TLX（使用官方说明与评分，不自行拼凑量表），并回答：“哪一步最费力？你是否知道哪些文字是原始素材、哪些还没完成？你认为系统替你决定了什么？”

## 盲评

运行 `node scripts/prepare-creation-review.mjs` 生成两份匿名文本与评审说明。只将 `blind-packet/` 提供给未参加设计的评审者，勿发送 `blind-key.json`、截图、代码或来源文件名。A/B 随机化只隐藏出处，文本结构仍可能暴露版本；记录评审者猜测出处及信心。

评审者同时得到原始任务材料，按下列维度独立评分，至少两名评审者；分歧保留，说明仲裁依据，不只取对自己有利的分数：

1. 素材忠实度：是否保留关键数字、限定条件、作者措辞，是否误归因？
2. 意图与观点：是否响应主题，是否替作者捏造立场？
3. 事实边界：是否将未读链接或个别经历写成确定事实？
4. 结构与可编辑性：是否知道下一步该改哪里？
5. 完整度与剩余劳动：还需多少编辑才能成为可用内容？

每项 1–5 分：1 为严重问题，3 为可继续但需明显修改，5 为达到任务要求；同时标出原文位置和理由。编造事实或遗漏关键限定条件单独标为阻断缺陷，不允许高平均分掩盖。记录实际补写/修订用时后再判断总体负担；初稿更短、占位更多可能只是把工作留给作者。

当前两份文本均是 Mock，盲评只能评估这两份底稿，不能证明真实模型的生成质量。没有真实评审前，blind-review.csv 保持仅表头。

## 通过条件

操作减少必须伴随独立完成率和质量不下降，且恢复成本可接受。正式比较需预先声明改善目标、质量与成功率的非劣效界限及样本量；小样本阶段只报告观察到的障碍和个案，不宣布产品整体成功。
