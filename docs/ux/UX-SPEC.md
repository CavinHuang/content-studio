# Content Studio · UI/UX 规范 v1.2

> 当前视觉基础：[设计系统 v2.2](DESIGN-SYSTEM.md)。色彩遵循已确认设计稿；字体、间距与控件尺寸采用 Tailwind + shadcn 默认规范。作品隔离、创作、版本、热点与发布交互继续有效。

日期：2026-10-25。面向个人内容创作者。本文记录已确认方向与本轮补齐设计；是后续实现的产品交互依据。

## 1. 范围与目标

帮助创作者把零散素材变为有个人观点的内容，制作平台版本和视频作品，并自行完成最终发布。

目标平台：公众号、小红书、知乎、抖音、X。平台版本按表达方式区分，具体长度等是可修改的建议，不将示例字数固化为平台上限。

桌面承担完整创作；手机承担随手收集、查看进度、Agent 沟通和简单文字修改。当前发布通过预览、复制、下载或导出交付内容，用户手动发布并记录结果。

## 2. 信息结构

左侧保留「热点」、全局素材库与内容库入口；中间显示当前产物；右侧保留当前 Agent 对话。热点是全局发现入口，不作为每篇内容的产物标签。内容项目与对话分别管理，切换对话不切走当前文稿，切换内容后恢复该内容的最近工作位置与关联对话。

每个内容项目包含：

- 创作方案：选题、核心观点、目标读者、表达风格、篇幅建议和大纲。
- 文稿：母稿和各平台的独立版本。
- 视频：多个独立视频作品，每个作品有固定制作方式。
- 参考素材：指向全局素材的本篇引用。
- 发布记录：按发布批次和目标平台记录选择、导出版本、状态与链接。
- 创作来源：若从热点发起，保留原热点、采用的角度与所选来源快照，可回到来源查看。

顶层产物标签统一为「创作方案 / 文稿 / 视频 / 素材」。顶部保留「发布准备」入口。

本篇引用、对话引用、文稿插入是不同动作。移除项目引用不会删除原素材，也不反向删掉已经写进正文的文字。

## 3. 桌面布局与视觉基准

桌面分栏以设计系统 v2.2 为准：默认左 256 px、右 384 px，1480 px 窗口中间约 838 px；窄桌面优先保留中间可编辑空间。左右均可收起，分隔线支持拖动，编辑区宽度优先。恢复时记住用户上次宽度。

1280 px 以下可折叠内容库；宽度不足以容纳三栏时，Agent 采用可切换抽屉，不强行压缩正文。平板采用工作区加可切换 Agent，手机使用独立单列布局。具体断点以内容是否溢出决定，候选断点为 1280 / 1024 / 768 px。

界面字体使用 Tailwind 默认 font-sans 与 text-sm；文稿标题使用 text-3xl，正文默认 sans / 16px / leading-7。用户可按平台版本调整内容排版。页面组合使用 p-4、gap-3、gap-2 等 Tailwind 刻度；Button 与 Input 保持 shadcn 默认 h-9，不用旧设计稿中的尺寸覆盖组件。

文稿优先于卡片。任务、素材和建议可使用轻量卡片；不把每段正文包成卡片，不让临时设置变成固定第四栏。颜色同时配合文字、图标与状态名称，最终实现需检查实际配色对比度。

## 4. 新建内容与创作方案

点击「新建内容」直接进入空白工作台。中间可立即输入标题或正文、拖入素材；右侧邀请用户说一个想法、粘贴链接或上传素材，无必填主题表单。另提供「从热点找选题」快捷入口，跳转热点发现页；从热点选定角度后发起创作的流程见第 20 节。未命名内容用第一条有效标题或用户指定名称命名，可随时改名。

快捷提示只填入对话输入框，由用户发送。Agent 先整理方向和大纲，方案在中间作为可编辑产物呈现，聊天里只保留摘要和跳转引用，避免重复大段方案。

选题、观点、读者、表达、篇幅建议均可直接修改；大纲支持添加、删除和拖动排序，也能通过 Agent 调整。唯一主要动作是「确认方案，生成母稿」。直接写作的用户可以自行完成母稿，再发起平台适配，不强制补填方案。

更改已确认的方案不自动重写现有文稿。用户明确要求生成新稿时，保留之前的稿件版本。

## 5. 文稿与 Agent 协作

中间支持编辑、预览；Markdown 内容与 doocs/md 的排版能力整合是目标。设计稿没有证明实际嵌入已实现。产品应围绕当前文稿提供选中文字、插入、替换和恢复操作。

选中段落后，可「交给 Agent」并在输入框中形成显式上下文引用；用户发送后才执行。默认范围显示为所选段落，没有选择时显示当前文稿。涉及多篇、多个平台或整篇替换时，在操作与建议中明确范围。

内容类 AI 修改以原文与建议对照显示。采用后创建版本并支持撤销；保留原文时正文不变。多条建议支持逐条采用，也可在明确范围后全部采用。原文已被手动修改时，建议标记为过期，要求重新生成或重新对照，不静默覆盖。

直接手动输入自动保存；AI 内容写入已采用稿件需要用户采用或明确授权。新建空白草稿中的首次生成可以直接形成初稿，后续修改遵循版本与采用规则。

## 6. 母稿与平台版本

母稿是来源，各平台版本独立编辑、保存与排版。每版记录来源母稿版本，展示「基于母稿 vN」。

公众号：长文；小红书：标题、图文文案、话题；知乎：问题与观点回答；抖音：口播脚本与关联视频；X：串文及段落顺序。长度建议与各类字段可修改。

可以生成一个或多个平台版本，不要求一次生成全部。再次生成时创建候选版本，已经手改的内容保留；母稿更新后提示来源已更新，由用户决定要同步到哪些平台。正文、排版、话题等按各自版本保存。

编辑与生成范围必须显式显示：当前平台、所选平台，或全部平台。生成过哪些版本与本次发布哪些平台独立。

## 7. 排版

点击「排版」在中间工作区内展开临时浮层。提供主题、字体、字号、行高、段落间距、页边距；预览实时反映样式，完成后保存到当前平台版本。恢复默认只恢复本版样式，不修改文稿内容。

文章主题与视频主题独立，不因修改 App 视觉或某篇文章主题而联动全部视频。文章富文本复制与各平台导出格式需要实机验证；界面提供清楚的格式选择与结果反馈。

## 8. 素材收集与复用

全局素材支持文字、链接、文件与图片；标题、来源、标签可后补。只有有效正文、链接或成功上传的文件才可保存。链接保留原 URL、采集时间和提取状态；提取失败仍可保存原链接，并允许粘贴正文，不伪装读取成功。

从项目中收集时可勾选「同时引用到当前内容」；勾选后的主按钮为「保存并引用」，取消勾选为「保存素材」。从全局入口收集不默认绑定当前项目，允许选择关联内容。AI 提炼要点可选，不作为保存的前置条件。

项目素材页有「本篇引用 / 全部素材」范围切换、搜索与类型/标签过滤。素材列表可展开原文、查看来源和被哪些内容引用。

关键动作：

| 动作 | 结果 |
| --- | --- |
| 引用到本篇 | 建立项目关联，不自动插入正文 |
| 引用到对话 | 形成待发送的对话上下文，不自动发送 |
| 插入文稿 | 将选定片段或素材插入指定文稿位置，支持撤销 |
| 移除本篇引用 | 解除本项目关联，原素材和其他引用继续保留 |
| 删除原素材 | 在全局库显示受影响引用，二次确认后移入回收站 |

正文引用保存当时的片段与来源，之后素材更新不反向改写旧稿；项目可查看新版本，主动更新引用。只有本篇已关联的素材默认进入该内容的创作上下文；用户明确让 Agent 检索素材库时，可以检索其他素材并给出候选引用。

## 9. 视频入口与两条路线

进入「视频」后展示已有作品和「新建视频」。新建时选择制作方式与来源：当前母稿、已有文稿或新想法。选择方式后创建独立作品，不通过模式切换覆盖另一种作品。跨路线复用内容时创建新作品并标明来源。

| 素材分镜 | Agent 代码创作 |
| --- | --- |
| 脚本、素材驱动 | 创作说明、视觉参考、动画意图驱动 |
| 分镜编辑 / 配音与字幕 / 成片预览 | 作品预览 / 创作说明 / 版本 |
| 换图、调口播、字幕与镜头顺序 | 预览、场景结构、显式可调参数、对话迭代 |
| 场景素材与时长组成视频 | Agent 维护动画代码及其输入数据 |

Remotion 与 HyperFrames 是渲染技术候选，不与产品里的两条制作路线一一绑定。首轮优先验证 Remotion；不在验证前承诺渲染耗时、局部编码加速或任意代码均可可视化编辑。

## 10. 素材分镜模式

分镜卡片是主要编辑界面。每个镜头有独立 ID、顺序、画面描述、素材、口播、字幕、时长和相关版本。支持拖动、添加、删除、换图、替换上传素材、指定镜头交给 Agent。

「配音与字幕」提供试听、声音与语速选择、字幕文字与起止时间修改。声音列表来自实际服务能力；不把设计示例当成必须存在的供应商声线。

字幕校对支持按条选择；重新生成配音显示作用范围。修改口播后，对应配音显示待更新；新配音长度影响本镜头及之后的时间位置。手改字幕文字保留并提示重新校对时间，不无声替换。SRT 输出文字与时间戳，字幕字体、颜色与位置属于成片样式设置。

成片预览联动镜头缩略条。选中镜头可改画面文字、动效和转场；全局音乐、比例、分辨率、字幕样式通过临时「视频设置」调整，明确显示全片范围。

## 11. Agent 代码创作模式

从创作说明与参考开始。Agent 先给出视觉方案与场景结构，用户可修改并确认，再生成第一版可预览作品。核心界面是播放器、场景结构、候选版本和对话；不是素材分镜表的另一种皮肤。

场景可选择并通过对话指定修改范围。界面只显示实际声明的可调参数，例如强调色、标题文案、动画间隔；不假设每段任意生成代码都有可拖拽图层映射。「查看代码」属于高级折叠入口，默认不占据主画布。

区分「当前已采用 v2」和「正在预览候选 v3」。候选可对比、采用、拒绝；采用前仍可导出明确标记的已采用版本。生成失败保留上一可用作品。编译日志折叠，默认用创作者能理解的错误与修复动作描述问题。

手动修改参数与高级代码操作均建立版本。Agent 新候选基于明确的源版本；源版本变更时不能无提示覆盖。用户只改变某场景的意图，不等于承诺 MP4 只重新编码该场景。

## 12. 视频输出与任务恢复

预览可播放不代表文件已导出。正式导出固定采用的作品版本与素材快照，任务期间继续编辑不改变已在导出的快照。作品有更新时，旧成片显示「历史版本 / 未包含最新修改」。

导出可选择比例、分辨率、帧率、格式。默认参数建议 9:16 / 1080 × 1920 / 30 fps / MP4，实际选项受运行环境与编码支持限制。视频与素材包为独立动作；素材包可包含脚本、分镜图、配音与 SRT，按可用资产说明内容。

统一任务状态：

| 状态 | 显示与动作 |
| --- | --- |
| 排队 | 已提交、等待开始；可取消 |
| 运行 | 显示当前步骤与真实进度；支持的任务可停止 |
| 部分完成 | 已完成产物可用；可重试失败项 |
| 失败 | 显示影响范围、简短原因、重试或替换素材；详情折叠 |
| 已停止 | 保留已完成内容与最后可用版本；可明确重新开始 |
| 完成 | 显示输出版本、可预览或下载；不等于已发布 |

无可用真实进度时显示步骤而非伪百分比，不承诺准确 ETA。重试沿用明确的版本和范围，避免重复启动同一任务；取消和关闭页面不等价。离开或关闭桌面程序前，告知尚在本机运行的任务会受何影响。

## 13. 版本历史与恢复

文稿、平台版本、视频作品分别有自己的历史。自动保存与可恢复版本快照是两个层次：手动修改、采用 Agent 修改、生成或导出等重要节点形成明确记录。历史可比较原文、建议或已采用版本；新增/删改使用颜色加文字标识。

恢复旧版创建新版本，保留恢复前当前版本和完整来源，不破坏分支历史。恢复只作用于当前文稿或作品，不联动覆盖其他平台。导出文件记录所用快照，恢复编辑版本不改写已经导出的文件。

## 14. 发布选择与人工交付

发布准备首先选择本次平台。支持多选、全选、清空；未选平台的内容继续保留。没有发布历史的新批次默认不强选全部平台，沿用选择时需明确显示并允许改动。

选中了尚未生成或未准备好的版本，显示具体缺少项并提供准备入口；其他已选平台可继续单独处理。批量导出前显示实际包含哪些版本与文件，缺失项不得静默当成成功。

平台预览和动作按内容形式变化：公众号富文本复制；小红书正文、话题、图片；知乎问题与回答；抖音选择某个已采用视频作品、口播或素材包；X 串文按段复制或导出。

发布记录绑定「本批次 + 平台 + 文稿/视频快照」。同平台有多个视频作品时，在准备阶段明确选择哪一部及其导出版本，支持回到制作界面处理待更新内容。

复制、导出与打开平台都不改变发布状态。用户手动发布后可标记已发布并记录链接，误标记支持改回。导出完成、正在准备、用户标记发布是不同状态。

## 15. 手机辅助

手机采用单列页面，底部主要入口「收集 / 内容 / 任务」。素材收集支持文字、链接、图片和文件，可选关联内容；暂时无网络时保留本机草稿并明确提示待上传，不显示虚假云端成功。

内容页可预览、简单改字和进入 Agent；任务页显示状态、失败详情、支持的取消/重试。复杂分镜与动画修改引导回桌面。手机改稿与桌面同时编辑时提示版本变化，保留两边内容供恢复，不悄悄覆盖。

手机与桌面同步属于实际存储/服务能力，需要后续技术验证；设计不把未实现的后台云渲染视作已存在。

## 16. 设置与首次可用状态

设置从左侧底部进入，中间显示设置页，保留返回工作台入口。分组为「AI 服务 / 创作偏好 / 数据与导出」。

AI 服务：文本、图片、配音分别显示是否可用、选择服务与模型、测试连接；只有需要用户配置的服务才显示相应输入，凭据默认遮挡。未配置时仍可写作、浏览本地素材和管理版本；执行依赖该服务的动作时给出就地配置入口并保留当前上下文。

创作偏好：常用平台、默认语言、表达偏好、视频默认比例、排版预设；项目和版本可覆盖默认值。默认偏好不改变本次发布平台的显式选择。

数据与导出：存储位置（仅在运行形态支持时）、导出项目与全量备份、导入与恢复说明。删除内容或原素材统一使用回收站与影响提示，不使用与移除引用相同的含糊按钮。

## 17. 可访问性与细节

按钮、标签、复选框和对话输入均可通过键盘操作，焦点清晰；弹层支持 Escape 并返回触发控件，抽屉和弹层有清楚标题。状态变化通过可感知消息反馈，避免仅颜色或瞬间 toast。

保存状态包含「保存中 / 已保存 / 保存失败」，失败时保留未保存内容并允许重试。输入法组合输入期间不抢焦点或提前发送。默认 Enter 发送、Shift+Enter 换行，允许设置为相反习惯；首次输入框给出简短提示。Ctrl/Cmd+Z 的作用范围是当前编辑区，不能意外恢复整项目。

空列表给出下一步；加载失败保留可用内容；长标题截断有完整名称入口；长对话与素材列表可渐进加载；生成中支持在不受影响区域继续编辑。涉及丢弃未保存内容或全局删除才询问，普通切换和可撤销操作不反复弹确认。

## 18. 后续实现验收依据

1. 三栏比例可调整与收起，手机不压缩为三栏。
2. 空白项目可直接写作或对话开始，方案可手改后确认。
3. 选中文本传入输入框；AI 建议有范围、对照、采用与撤销；过期建议不覆盖。
4. 母稿、平台版本和排版独立保存，来源可追溯。
5. 全局素材可跨项目复用，引用、插入、删除的结果各不相同。
6. 两条视频路线创建独立作品，有各自的制作界面与版本。
7. 字幕文本、配音和时间更新状态明确，手动校对内容可恢复。
8. 预览、采用、导出和发布四类状态分开；旧成片明确标记来源版本。
9. 任务停止或失败保留成果，可重试受影响范围，不虚报进度。
10. 旧版恢复创建新版本，跨平台内容不被连带覆盖。
11. 发布平台由用户显式选择，未选版本保留，抖音输出选择明确的视频作品。
12. 图像设计中的示例数值不作为平台规则；实际复制、编码、服务与同步能力经过技术验证后启用。

## 20. 热点发现与从热点发起创作（v1.1 新增）

### 20.1 入口与发现

左侧增加独立「热点」入口，位于素材库与内容库之前，桌面保持三栏。中间浏览热点或话题详情，右侧 Agent 围绕所选热点分析与讨论。新建内容的空白状态另提供「从热点找选题」，用户也可始终直接写自己的想法。

发现页支持搜索关键词、领域分类、信息源类型、具体信息源、时间范围以及最新/热度排序；提供来源管理、收藏、查看已有创作、刷新和「查看与创作」。领域为可调整偏好，首次使用不要求先填个人画像。收藏话题与将具体原文保存为素材是不同动作。

同一事件或话题的多个来源尽量聚合成一张卡片，展开后保留每条来源；不因标题相似就把不同事件当成同一事实。同一热点已有内容时显示「已创作 N 篇」并允许查看，用户仍可用新角度创建另一篇内容。

推荐说明给出与用户关注领域或已有内容的关系，不用没有依据的匹配百分比。没有个人偏好时直接提供分类和最新列表。

### 20.2 来源、热度与时间

热点来源与目标发布平台分别配置，不能因支持在某平台准备发布就默认拥有该平台的热榜或正文访问能力。来源列表根据实际接入能力启用；具体数据服务、刷新方式和连接方式待技术验证。

每条来源保留标题、原始 URL、来源名称、可获得的发布时间、采集时间与读取状态。事件发生时间、原文发布时间和本次抓取时间分别标注；无法获得的字段不伪造。无法读取正文时允许保存原链接、粘贴原文或换用来源，并明确标注「仅链接」。

各来源的排名和指标保留原含义，不把不同平台的原始数值直接相加。综合排序如果采用产品自己的规则，界面提供「排序依据」说明；缺少可靠热度指标时仍可按最新排序，不虚构统一热度分。

AI 热点概览、背景归纳和建议角度与原文来源分开显示；没有读到的正文不生成带确定口吻的原文摘要。题图、日期和热度必须来自真实数据或明确的示意状态。当前效果图中的话题、来源与计数为设计示例，未接入实时榜单。

### 20.3 热点详情与选角度

「查看与创作」进入详情，而不是直接写完文章。详情包括话题概览、可勾选的来源、已有相关创作，以及可编辑的创作切入点。

Agent 可建议几种角度，例如个人经验、方法整理、观点分析；用户可以单选、改写或自行输入。选中的角度、当前热点与来源范围在右侧对话输入框中可见，支持继续收窄选题。事实背景、AI 提议和用户经验区分保存，不替用户虚构经历。

主动作「用这个角度开始创作」会：

1. 创建一个新内容项目，记录热点关联和此次选题快照；防止一次点击重复创建。
2. 带入选定角度、用户补充要求及勾选的来源；可读取的原文片段保存为素材引用，仅链接的来源保持相应状态。
3. 将右侧上下文切换到新内容，保留这次发起创作所需的信息，不把热点页其他无关对话塞入新项目。
4. 生成可修改的创作方案，用户确认后再写母稿；需要做视频时也可从方案进入两条视频路线，无需强制先完成一篇长文。

本步骤不强制选定最终发布平台。文章适配和发布范围沿用现有独立选择流程，也不会覆盖已有内容或直接自动发布。

### 20.4 动态更新与状态

热点继续变化时，已创建内容保留原选题、已采用素材和来源快照。需要纳入新进展时显示可更新来源，用户选择补充哪些内容，Agent 生成候选修改，不静默重写旧稿。

状态覆盖：加载、没有数据、筛选无结果、部分来源失败、数据过期、收藏为空、生成角度失败和新建内容失败。刷新失败时保留上次可用数据并显示其更新时间，不能把旧数据标成刚更新；来源失败只影响对应部分。角度生成失败仍允许手动输入角度与继续创作。

未完成切入点的输入在切换热点时保留为草稿；返回发现页保留筛选与滚动位置。手机可以浏览、收藏热点、选择角度并创建内容，后续完整制作可回桌面；不扩展为无人确认的自动追热点或自动发文任务。

### 20.5 新增验收依据

1. 全局热点与项目产物分开，创建后能回查原热点与来源快照。
2. 发现 → 来源与角度 → 新内容创作方案 → 文稿或视频，整条路径连通。
3. 用户能改写角度、增减所选来源，并从同一热点创建多篇独立内容。
4. 热度、来源和时间的含义可识别，未接入和仅链接状态不伪装成功。
5. 热点后续变化不覆盖现有稿件，更新仍经过修改建议与采用流程。
6. 新增入口不改变发布平台选择、版本隔离和两种视频制作路线。

### 20.6 多信息源与来源管理（v1.2 新增）

热点按「多个信息源 → 话题聚合 → 来源选择 → 创作」设计，信息输入不限于五个目标发布平台。信息源作为全局配置独立管理，不把目标发布平台复选框直接复用为来源配置。

来源类型至少区分：

| 类型 | 内容与操作 |
| --- | --- |
| 平台热榜 | 某平台的榜单或话题频道；保留来源内排名和指标含义 |
| 新闻资讯 | 媒体、资讯网站或已接入的新闻频道；保留发布者与原文 |
| RSS | 用户订阅的 Feed；按订阅与文章分别管理 |
| 自定义来源 | 通过实际支持的导入或连接方式加入的来源，未接入时显示未配置 |

来源管理从热点发现页的「来源管理」进入，中间显示列表，右侧 Agent 保留。每个来源有显示名称、类型、领域、接入/读取状态、启用状态、最近成功更新时间及设置入口。可添加来源、单独启停、编辑 RSS 订阅、配置、刷新或重试；只有运行方式允许时才展示更新频率等设置。

默认创作者视图不堆放接口参数或凭据，需要的连接配置收在具体来源设置中。来源状态区分可用、未配置、已停用、更新中、获取失败与缓存过期；「开关开启」表示纳入后续更新，不能当作连接成功证明。新增来源和具体平台可用性依赖实际连接能力；效果图名称只是候选来源示例。

聚合模型与详情：

1. 一个话题可以关联多个信息源，一个信息源可以提供多篇相关原文；「N 个信息源」与「M 篇原文」分别计数，卡片可展开来源清单。
2. 同一原文被多个渠道收录时，按可识别的原始 URL 等信息合并，保留「由哪些源收录」；不能把重复转载数量当成独立证据数量。
3. 热点详情按信息源分组或筛选原文，支持查看全部来源、保留链接、选择引用的具体原文；勾选源时显示实际将带入多少篇，用户可逐篇增减。
4. 观点不一致的原文分别保留，不让 AI 聚合摘要抹平差异；角度建议可以建立在讨论差异上，但不把推断当作原文事实。
5. 排名与热度按来源展示，综合聚合可按时间、来源覆盖等可解释规则排序，不直接加总不同榜单原始数值。
6. 过滤器中区分「领域」和「来源类型/具体来源」，允许只看新闻、只看某个 RSS 或查看全部聚合话题。来源状态与最近成功更新可回查。

停用一个信息源只停止后续获取，保留已经保存的原文、素材、引用及创作快照；移除来源时说明其对后续更新的影响。一个源失败时继续展示其他可用来源与可识别的旧数据，不把整个热点页变成空白。

新增验收：来源可独立配置和启停；聚合话题能追溯全部收录源与去重原文；来源数量、原文数量和发布平台数量不混淆；故障与停用不破坏已有创作。
