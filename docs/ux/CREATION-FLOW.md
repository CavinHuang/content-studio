# 从想法与原始记录到母稿：交互重构

> 后续布局修复已将起步输入、文稿工具栏与候选比较分离：新建仅一个输入，调整方向按需打开，比较临时占用正文工作区，导出固定在文稿工具栏。界面位置和最新数据以 [布局修复记录](LAYOUT-FIXES-2026-10-26.md) 为准；下文保留首次原型的研究过程。

> [连续操作修复](LAYOUT-FOLLOWUP-FIXES-2026-10-26.md) 进一步将方案生成并入同一快照与候选流程，实际整理任务接入任务中心，手机可直接新增平台稿；下文对旧方案未使用素材的观察为修复前事实。

本轮集中在一条任务：新建内容 → 提供主题与零散文字/已有本篇素材 → 整理出可编辑底稿 → 校订 → 导出 Markdown。平台适配、热点、视频和对外发布均沿用现有路径。实现为 Electron 内可操作原型；整理器为可替换的本地 Mock，未接模型。

## 验证前确定的成功标准

以下标准在新流程测试前写下，不是测量结果。

- 同一组合成原始输入下，生成流程的显式操作（点击与输入提交分别记）较基线减少至少 30%，不靠省略作者校订获得改善。
- 输入只录入一次；已有本篇文字素材自动带入，保留来源、原始输入和生成快照。未读取的链接、图片、文件必须明确说明，不能当作证据。
- 首次整理仅能写入未变更的空白母稿；已有正文、生成期间的手改和其他项目均不可被自动覆盖。候选必须先比较再主动采用，替换可恢复。
- 信息不足只询问缺少的主题；失败、停止、改方向、重启后不要求重新提供原始素材。重复点击不重复生成，过期回调不写入。
- 当前正文可编辑，Markdown 下载必须逐字对应当前标题与正文，导出不改变发布状态。
- 事实与立场不得凭空补写。真实创作质量、完成率、时间和主观负担必须由目标用户及盲评验证；程序测试不能判定这部分已通过。

## 证据与选择理由

已观察事实（静态代码）：

1. `studio/store.tsx` 的原 `generateArticle()` 只将 title 与 brief 交给 `mock.ts/generateBody()`，不读取 `materialIds`。素材已被引用不意味着生成正文使用了素材。
2. `pages/Materials.tsx` 区分存储、引用、插入；素材创建有独立弹窗。`pages/Brief.tsx` 要求主题、核心观点及非空大纲后才能生成。用户已经说过的意图需要手工转成另一份状态。
3. 导出母稿原来位于工作区“更多操作”；发布准备承担平台交付，不应成为母稿下载的先决条件。
4. `readState()` 会停止重启前的模拟任务，但没有本轮原始输入/生成快照的专用恢复状态。
5. README 说明当前 AI 全为本地 Mock，没有真实模型、抓取或自动发布。

选择这条任务是因为它跨越素材、方案、正文、导出四个现有职责，且可通过实际下载验证终点。根因假设是“状态分散和上下文未被消费造成用户衔接工作”；不能从代码推断真实用户发生问题的频率。

没有用户访谈、使用录像、生产点击日志或真实创作样本。本轮测试夹具是刻意保留数字、措辞和来源的合成记录，不能冒充原始用户研究。旧设计稿只作背景参考。

## 任务分析与认知走查

| 用户目标 | 原路径与系统已知信息 | 用户承担的劳动 | 新路径与新增交互的理由 |
| --- | --- | --- | --- |
| 留住想法和笔记 | 分别创建素材、引用并填写方案；系统已有本篇素材与偏好 | 切页、分类、再写主题和观点 | 一个原始输入区：第一行为主题，其余是未整理记录；减少录入和分类。只有主题缺失才询问 |
| 使用已有素材 | 已知 materialIds，但原生成器不使用 | 插入正文或自行重新整合 | 自动快照本篇素材；折叠的原文检查用于核对范围，默认无需点击 |
| 得到第一份正文 | 先确认方案，生成后页面切换 | 承担流程衔接与大纲准备 | 空白稿直接整理，正文仍可手写；一键撤销消除首次自动写入的恢复负担 |
| 改方向 | 需要再次编辑方案，原生成会产生新版本 | 自己记住旧稿、跟踪新结果 | 同区调整输入，已有正文只产生候选；比较和采用是保留作者重要变更判断所需的操作 |
| 交付底稿 | 更多菜单或平台发布流程 | 找到导出入口 | 同区直接下载 Markdown，减少导航与平台决策 |
| 失败后继续 | 通用模拟任务重试并不重放原生成逻辑 | 返回原页面重新组织上下文 | 原地继续，复用输入与本篇素材；快照和版本用于验证何时需要重新生成 |

认知走查结论是设计推断：主按钮描述产物，状态在原地；不依赖右侧会话或新导航入口。真实用户能否理解第一行约定、底稿与成稿差别，以及候选比较成本，均待观察。

## 人机职责与状态转移

用户决定主题、观点、正文修改、候选采用和导出。系统负责保留原始输入、复用本篇素材与偏好、生成快照、隔离任务、版本保存和过期检测。不会使用全局未引用的素材，也不会凭空选择作者立场。

| 起始状态/事件 | 下一状态 | 自动行为与恢复成本 |
| --- | --- | --- |
| idle → 整理，缺少主题 | blocked | 原地提示；仅补一行即可，所有原文保留 |
| idle/blocked/failed/stopped → 整理，信息够用 | running | 固定输入、作者观点、素材内容与来源、偏好；只等待一次本地 1 秒模拟 |
| running → 成功，母稿仍为空且未变化 | ready | 写入新版本，保留整理前状态；一键撤销。没有“确认方案”步骤 |
| running → 成功，已有正文或正文/标题有变化 | candidate | 原稿不变，比较后才能采用；有并发修改时禁止替换，需重新整理一次 |
| running → 失败/主动停止 | failed/stopped | 输入和母稿不变；一次继续操作与一次模拟等待，无须重录 |
| running → 修改输入 | idle | 取消旧 runId，旧回调失效；修改后再整理 |
| running → 关闭/刷新 | stopped | 从本地存储恢复输入和上次快照，用户主动继续；不会静默启动 |
| candidate → 采用 | ready | 检查母稿、输入、素材与偏好是否仍一致；创建保留原稿的版本 |
| ready → 撤销 | idle | 只在母稿仍等于本次产物时允许；后续有手改时通过版本历史主动恢复 |

Mock 底稿由原始摘录、作者已有观点和明确的待补写位置组成。它没有完成语义整合、事实核查或风格改写。即使操作指标通过，也不能宣布达成“可直接发布的成稿”，需要真实模型及盲评才能验证。

## 测量口径与复现

`tests/smoke/creation-baseline.spec.ts` 保留原素材→方案路径；`creation-flow.spec.ts` 走新路径；两者用相同主题、原始记录和作者校订句，下载并读取实际 Markdown。基线首次在改动前的构建中采集，原路径也保留供重跑。

`research/creation/baseline.json` 与 `prototype.json` 记录逐步动作。脚本 `fill` 是一次输入操作，不是一个键击，也未计为真实鼠标点击；不虚构输入时长、阅读时长、认知决策数或主观负担。`elapsedAutomationMs` 包含 Playwright 等待与自动化调度，只能诊断脚本，不代表人类节省时间。跨页次数含生成完成后的自动导航。一次固定模拟等待不等于真实模型延迟。

复现：先 `pnpm exec tsc --noEmit`、`pnpm build`、`pnpm design:check`，再 `pnpm exec playwright test`。界面测试需要启动 Electron。功能、故障注入、窄屏和对照测试结果与截图见研究目录；最终结论另见 `research/creation/RESULTS.md`。
