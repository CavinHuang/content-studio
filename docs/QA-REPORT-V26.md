## 主要通过项

- 新建与修订文稿，旧版本不变；提交陈旧修订号得到 409。
- 段落 ID 唯一，锚点必须是段落内部存在的原句；证据 ID 必须属于同一知识卡修订。
- 同一研究版本变化的重复扫描不会产生重复更正任务。
- 研究再次变化后旧任务无法以陈旧知识版本执行。
- 保存人工修改提案不自动更改正文；显式确认才原子写入本地稿新版。
- 本地导出稿不能登记为“外部已更正”。
- 修订后旧锚点显示 `quote_changed`，删除段落后显示 `paragraph_missing`。
- 原公众号稿、知乎稿独立，内容不会静默跨渠道修改。
- 本地 HTTP Origin 限制（携带非同源 Origin 时拒绝写请求）。
- UI 测试通过真实 HTTP API 完成段落保存→证据绑定→研究重开→更正建议→批准→新文章版本。

## 重要测试限制

这些结果表明本地模拟/受控数据路径可运行，不意味着用户真实需求、新闻可信性、外部文章状态或实际更正已验证。浏览器测试使用 Python 代理将 UI 的 `fetch` 转发到 Node HTTP 服务，**不能证明浏览器已通过原生网络栈直接访问本地地址**。真实运行环境的缓存、跨刷新持久化及平台复制/富文本一致性仍须单独验收。
